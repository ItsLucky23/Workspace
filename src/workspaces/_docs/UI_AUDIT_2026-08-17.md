## 2. Duplicaat-concepten (informatie-architectuur)

Dezelfde zaak op meerdere plekken, zonder dat de UI de relatie uitlegt. Dit is het type probleem dat alleen zichtbaar wordt als je alle pagina's naast elkaar legt.

### AI prompt layering in the Develop pipeline (the one the owner already spotted, plus its two hidden siblings)

**Waar:** `src/workspaces/workspace/page.tsx:1002-1009 (workspace `aiInstruction`)` · `src/workspaces/workspace/page.tsx:946-973 (AI Skills instructions + 'apply points')` · `src/workspaces/develop/pipeline/stageTabs.tsx:54-56 (per-stage `systemPrompt`, hint: 'layered above your instructions')` · `src/workspaces/develop/pipeline/stageTabs.tsx (per-stage `customInstructions` → the stage's CLAUDE.md)` · `src/workspaces/develop/pipeline/stageTabs.tsx (Carry-over `promptTemplate`)` · `src/workspaces/develop/board/[ticketId]/page.tsx:513-519 (stage config shown read-only, no link to the layers)`

**Wat een gebruiker niet kan zien:** Five free-text fields shape one agent prompt and nothing states the order. 'Layered above your instructions' never says above WHAT. A user editing seven stages plus the workspace cannot tell whether the workspace instruction is a default stages extend, a floor that always applies, or something a stage silently overrides — and the code comment at workspace/page.tsx:851-855 acknowledges the relationship exists but it was never surfaced.

**Voorstel:** Ship `EffectivePromptPreview` (sharedFix 11) on the stage General tab and under the workspace instruction textarea: a Disclosure rendering the composed prompt in real order, sourced from one `resolveAiLayers()` helper. Add an inheritance badge next to each field ('layer 3 of 5 — runs after Workspace + Skills') and one line of hint copy naming the order. Ticket detail links to the preview instead of showing a dead read-only chip.

### AI steering in Content/Studio/Marketing — a second, unrelated layering stack

**Waar:** `src/workspaces/content/studio/page.tsx:328-329 (brief.tone / goals / notes)` · `src/workspaces/content/studio/BrandPanel.tsx:105 (workspace-wide brand.voice)` · `src/workspaces/content/studio/page.tsx:257-264 and content/marketing/page.tsx:41,53-58 (per-generation `refine`)` · `src/workspaces/content/settings/ChannelsTab.tsx (channel brandVoice + defaultStyleId)`

**Wat een gebruiker niet kan zien:** brief.tone says 'playful', brand.voice says 'formal' — the user has no way to predict the output, and brand.voice is a workspace singleton that may not apply to this brief at all. Worse, in marketing `refine` is one shared state used by every generate AND every card's Regenerate, so a stale refine string silently applies to an unrelated older card and no artifact records which refine produced it.

**Voorstel:** Same `EffectivePromptPreview` component, second profile: show the resolved steering ('refine > brief tone > brand voice > channel voice') as a chip row above the generate button. Persist the refine string onto each artifact and show it in the card's metadata row + next to Regenerate, or clear `refine` after each generate.

## 3. Productbeslissingen (voor de eigenaar)

Deze kan geen agent beslissen — het zijn keuzes over wat het product moet dóén, niet hoe het eruitziet.

**V1. Does a per-stage AI persona combine with the workspace-level AI instruction, or replace it?**

- *Waarom het uitmaakt:* Five prompt-shaping fields feed one agent and the composition order is only knowable by reading server code; every UI fix here (badges, effective-prompt preview) depends on the answer, and it is the owner's own flagged issue.

- Strict layering: workspace → skills → stage systemPrompt → customInstructions, always concatenated in that order
- Stage overrides: a non-empty stage systemPrompt replaces the workspace instruction entirely
- Per-stage opt-out: layered by default with an 'ignore workspace instruction' checkbox

→ **Advies:** Strict layering, with the effective prompt visible as a preview — override semantics are invisible failure modes and the current hint copy already implies layering.

**V2. Who owns a channel's brand voice — Content Settings → Channels, or the Insights BrandCard?**

- *Waarom het uitmaakt:* The same field is written by two different mechanisms (control-API op vs sync op) from two screens that do not know about each other; only one can be the record.

- Settings owns it; Insights becomes read + link
- Insights owns quick edits; Settings drops the voice field
- Both stay editable, both route through the same channel-edit op with a cross-link

→ **Advies:** Settings owns it — it already carries the four sibling channel fields, and Insights should be a reading surface.

**V3. Is /dashboard (src/dashboard/page.tsx) dead framework scaffold, or a route that should exist?**
