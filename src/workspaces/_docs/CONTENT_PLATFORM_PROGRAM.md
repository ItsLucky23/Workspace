## 0. How this run works (read first)

- **Waterfall per item:** schema → engine → client → **verify (dummy-data integration test)** → ADR → branch-log → commit. Each item is fully done, green, and committed before the next builds on it.
- **Minimize human input.** All scope is pre-decided (§1–§3). Do NOT stop to ask. If a genuinely ambiguous fork appears with no answer here, pick the most sensible default, log it as an `OPEN VRAAG` in the branch-log, and continue.
- **No API keys exist.** Every provider adapter ships a **stub/dummy mode** returning valid-SHAPED fake output (a fake asset URL + metadata + a declared cost). The whole pipeline is integration-tested end-to-end on dummy data. NEVER block the run waiting for a key. Live AI-output tests are a keyed follow-up.
- **Per-item verification is a real integration test** (`tests/integration/*.test.mts`, real Conductor + Mongo, self-cleaning via `_helpers.mts` — add each new model to `cleanupWorkspace`). Assert SHAPE/STRUCTURE invariants + budget + gate + posting-with-dummy, not exact generated bytes. Run: `node scripts/runWsTests.mjs <filter>`.
- **Gates per item:** `npm run prisma:db:push` (backend DOWN first — kill node procs to avoid EPERM), `npm run generateArtifacts`, `npm run lint`, `npm run build`, `npm run ai:lint`, then the test. All green before commit.
- **Commit discipline:** per item, author `ItsLucky23`, **NO Claude co-author trailer**, do **NOT push**, on `main`. `git status` before commit; stage ONLY your own files. Another AI may be active — NEVER touch/stage `scripts/prismaWithSecrets.ts`, `caddyRoutes.ts`, `editor*/page.tsx`.
- **Per item also:** an ADR (`docs/decisions/NNNN`, then `npm run ai:decisions`), a `branch-logs/main.md` entry + `INDEX.md` row, and refresh the relevant memory note.
- **All framework rules apply:** file-based routing, function-injection, strict typing (NO `as any` / `as unknown as T` — run `npm run generateArtifacts` first), `functions.tryCatch`, **i18n ×4 (en/nl/de/fr) mandatory**, Tailwind theme tokens only (no arbitrary hex), surgical changes. **Reply in Dutch.**
- **The nine Workspaces invariants hold.** B-23 single-writer (AI proposes → user accepts → Conductor executes; LLMs never write authoritative state). Every user write = a `[control-API]` op. `runInTenant` on every orchestrator path. Media generation is NON-coding → MAY use other providers (ADR 0007); the PTY-billing rule binds only the *coding* agent.

## 2. Cross-cutting concepts (built early, everything depends on them)

1. **`projectType` lane** — `dev` | `content`; picks the workflow, stages, UI surface. Row-isolated per workspace (`runInTenant`).
2. **Media provider abstraction (extends ADR 0007)** — new `AiFeature`s: `image-gen`, `video-gen`, `tts`, `music`, `sfx`, `avatar`, `model-3d`, `reference-image`, `reference-video-analysis`. New `AiProviderId`s: `fal`, `elevenlabs`, `remotion`, `gemini-media`. Every adapter has a **stub mode**. Exhaustive `DEFAULT_ASSIGNMENTS` + per-workspace override (edit BOTH the union and the assignments map).
3. **Style/preset system** — a `StyleRegistry` per feature; a `StylePreset` model (global defaults + per-workspace). A generation = `runAiCompletion(feature, { input, style, extraInstructions })` → resolves the style's system-prompt preset. Seed default styles (e.g. `realistisch`, `cinematic`, `anime`, `low-poly`, `corporate`).
4. **€-budget** — a `MediaSpend`/budget model + a pre-generation guard in the control/gen path (stub adapters still declare a cost so the guard + caps are testable).
5. **Complete-output export** — a Remotion render → a downloadable final asset (the primary usable path while keys are absent).

## 3. The build items (execution order)

> Codes = phase.item. Each: goal → build (schema/engine/client) → verify (dummy-data test) → ADR → commit.

### Fase 0 — Fundament & contracten (schema-first)
- **F0.1 — Data-model + `projectType`.** Prisma: `projectType` on Project; `Channel`, `ContentProject`, `ContentAsset`, `Script`, `Beat`, `MediaJob`, `RenderJob`, `StylePreset`, `MediaSpend`. `runInTenant` + seq/merge event-log. Publishes the schema/types FIRST. **Verify:** create-workspace seeds a content project; the models round-trip row-isolated.
- **F0.2 — €-budget model + guard.** `MediaSpend` + per-workspace cap/alert; a pre-generation guard (`assertBudget`) enqueued before any gen op. **Verify:** a stub gen with a declared cost debits the budget; exceeding the cap blocks with a typed error.
- **F0.3 — Media provider abstraction + stub adapters.** Extend `AiFeature`/`AiProviderId`/`DEFAULT_ASSIGNMENTS`; Fal/ElevenLabs/Remotion/Gemini adapters with stub mode returning valid-shaped output. **Verify:** each feature resolves to its default provider; a stub call returns a shaped asset + cost; an unavailable real provider surfaces the typed unavailable error.
- **F0.4 — Style/preset system.** `StyleRegistry` + `StylePreset` (global + per-workspace) + `runAiCompletion(feature,{input,style,extraInstructions})` threading + seeded default styles. **Verify:** a feature+style resolves the right system-prompt preset; a per-workspace custom style overrides the global; extra instructions are appended.

### Fase 1 — Content-pipeline engine
- **F1.1 — Generic content-pipeline.** Content stages (idea→script→generate→assemble→review→publish) as the `content` lane + conductor stage-runner + control-ops (all `read|propose`, no new verbs — reuse the frozen surface + `WorkspaceTrigger` + run-command). **Verify:** a content project advances stage-by-stage via control-ops; the Conductor is the only writer.
- **F1.2 — Script + beats.** Script generation (LLM via `script` feature + style) → beat/storyboard split. **Verify:** a brief yields a shaped script with N beats; style + extra instructions flow through.
- **F1.3 — Voiceover.** ElevenLabs `tts` adapter (stub) + per-beat timing. **Verify:** a script yields a shaped voiceover asset + timing map; budget debited.
- **F1.4 — Image per beat.** Fal `image-gen` (stub) + style. **Verify:** each beat gets a shaped image asset; style applied; budget debited.
- **F1.5 — Assembly + export.** Remotion composition from the storyboard → `RenderJob` (stub render) → a complete downloadable asset. **Verify:** beats+voice+images assemble into a shaped final asset; the export/download path returns it.

### Fase 2 — Modaliteiten
- **F2.1 — Reference-driven photorealistic image-gen (#1 prio).** `reference-image` feature: reference input + `style: realistisch` + extra instructions (stub). *(Optional deeper sub-item: custom-model/LoRA training-from-references as a `MediaJob` kind — mark optional.)* **Verify:** a reference + style + extra yields a shaped image; the request carries reference+style+extra.
- **F2.2 — Short-form clips.** Fal `video-gen` (stub) + captions/hook. **Verify:** a prompt+style yields a shaped clip asset + captions; budget debited.
- **F2.3 — Reference-video analysis.** Gemini `reference-video-analysis` → a beat/style blueprint. **Verify:** a reference produces a shaped blueprint that seeds a new script.
- **F2.4 — Avatar / talking-head.** `avatar` adapter (stub). **Verify:** a script yields a shaped avatar-video asset.
- **F2.5 — Music / SFX.** `music` + `sfx` adapters (stub) into assembly. **Verify:** a render includes shaped audio tracks; budget debited.
- **F2.6 — 3D-concepting.** `model-3d` adapter (stub). **Verify:** a prompt yields a shaped 3d-mesh asset.

### Fase 3 — Publishing & automatie
- **F3.1 — Publish-gate + platform abstraction + YouTube.** A `PublishJob` behind a B-23 approval suggestion; a platform-adapter abstraction; a YouTube adapter (dummy — no real post). **Verify:** a completed asset creates a publish suggestion; accepting it runs the dummy YouTube post; no post without approval.
- **F3.2 — TikTok (+ IG/LinkedIn future-ready).** TikTok adapter (dummy); Instagram/LinkedIn registered as future adapters (not built). **Verify:** the dummy TikTok post runs via the same gate; the abstraction lists the future platforms.
- **F3.3 — Automation + conversational entry.** Cron content-triggers (recurring channel automation, reuse ADR 0027) + the Assistant conversational entry-mode (chat → an ephemeral content pipeline the user approves). **Verify:** a scheduled trigger runs a content-generation role to a suggestion (not a direct write); a chat brief spins up a content project.

### Fase 4 — Frontend & UX
- **F4.1 — Navbar refactor + lazy-loading.** Group the main navbar; add a **contextual 2nd navbar per area** (like tickets under pipeline); code-split/lazy-load heavy surfaces. **Verify:** build succeeds with split chunks; i18n ×4 for new labels; no arbitrary colors.
- **F4.2 — Content UI + settings.** Content-project board/pipeline/asset views + per-channel dashboard/analytics + a **style-picker** + a **settings-UI** (per-workspace provider + key). Real routes/pages (per the routing preference — no splat/query hacks). **Verify:** pages render the snapshot content-state; the style-picker drives a gen request; settings persist a provider override + (encrypted) key.
- **F4.3 — AI-drives-UI copilot.** The Assistant navigates + pre-fills forms + highlights → the user taps confirm (control-ops underneath, never pixel-clicking our own UI). **Verify:** a chat instruction navigates + pre-fills a content form; execution goes through a control-op behind confirm.

### Fase 5 — Geheugen & afronding
- **F5.1 — Per-channel brand-RAG + content-analytics.** Per-channel brand/style memory (reuse the single `retrieve()` + a channel sentinel) + a content-analytics fold (views/CTR placeholders on dummy data, extendable when platform keys land). **Verify:** brand memory conditions a gen; the analytics fold computes from seeded content assets.
